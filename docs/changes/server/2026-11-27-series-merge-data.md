# 系列合并关系的数据层支持

- 日期：2026-11-27
- 模块：server
- 类型：功能
- 涉及模块：server、shared（类型）

## 背景

同一部作品的第一季、第二季可能散落在不同的系列目录里，列表上就是多个互不相关的条目。此次为「首页拖拽合并」提供数据层支持：允许把一个系列并入另一个系列（后者成为主系列），并支持随时脱离。

合并关系存放在主系列的 `mergedIds` 上，被合并系列不保存反向引用——单一数据源，脱离时只需要改一处，不会出现两侧不同步。

## 数据模型

```jsonc
// 主系列
{ "id": "A", "mergedIds": ["B", "C"] }
// 被合并系列
{ "id": "B", "mergedIds": [] }
```

三条不变式：

1. 成员必须真实存在、不能是自身、同一列表内不重复；
2. 一个系列最多属于一个主系列（被多个主系列声明时先到先得）；
3. 不允许链式合并——被合并系列不能再持有成员。

第 3 条让「主系列本身又是别人的成员」这种手工编辑才会出现的数据有唯一解释，也让互相指向的环自然消解为各自独立，不需要单独的成环检测。

## 实现要点

1. **写入路径统一走 `addMergedIds` / `updateMergedIds`**，两者都过滤自身与重复项；`addMergedIds` 是追加语义，重复提交同一批成员不会写出重复项。
2. **`mergeSeries(sourceId, targetId)` 是展平合并**：源系列的成员一并转移给目标，源系列列表清空。拒绝三种情况——合并到自身、源系列已属于别的组、目标系列本身是成员（否则会形成链）。
3. **`detachSeries(mainId, memberId)`** 只改主系列，成员立即回到独立状态；成员不在组内时抛 400 而不是静默成功。
4. **规范化在扫描末尾执行**：`mergedIds` 的合法性依赖「全量系列是否存在」，只有 `getAllSeries()` 的全量视角能判断。规范化结果与内存值逐项比对，只有真正变化的系列才写盘，避免每次扫描都产生无意义写入。
5. **旧数据兼容**：`resolveSeriesConfig()` 在字段缺失时补空数组，历史数据文件不需要迁移。
6. **状态码走 `Status` 枚举**：参数级错误用 `Status.Failed`，不复用 404——系列存在但关系不成立不是「找不到」。

## 行为变化与兼容性

- 纯新增字段与新增静态方法，既有接口、既有字段读写全部不变。
- 新增字段在 DTO 中位于 `types` 与 `status` 之间，前端需按字段名读取，不要依赖键顺序。
- 扫描期规范化会重写数据文件中不合法的 `mergedIds`，这是唯一会改动已有数据的路径，且只在数据本身不合法时发生。
