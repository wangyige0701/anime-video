# Bangumi 同步范围扩展到合并组

- 日期：2026-11-28
- 模块：server
- 类型：功能

## 现象

主系列合并了另一个系列后，点「同步 Bangumi」只处理主系列自己的季：成员的季不在匹配列表里，也拿不到条目、标题与排序。详情页明明把两组季拼在一起展示，同步范围却只有一半。

## 原因

`BangumiController.localSeasons()` 只遍历 `series.seasons`，`applyChangeSet(series, input)` 的归属校验也只认主系列的季——成员的季一旦提交就会被判成「不属于该系列」，所以前面两步自然也不会把它收进来。

## 修复

把「主系列 + 被合并系列」当成一个整体处理：

| 位置                                                 | 改动                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------- |
| `BangumiController.mergeGroup()`                     | 按 `mergedIds` 取成员，悬空 id 跳过（数据层规范化会清理）                   |
| `readLocalSeasons()`（从 controller 抽到 `sync.ts`） | 遍历整组；成员季的 `path` 加「系列名 / 季目录名」前缀                       |
| `runMatch()` / `buildKeywords()`                     | 额外接收成员标题参与搜索：续作常是另一个名字（「微速前进」/「微速前行！」） |
| `runPreview()`                                       | 无需改动，入参已是整组季                                                    |
| `applyChangeSet(group, input)`                       | 按 `seasonId` 跨系列查找季；系列字段仍只写主系列；保存等整组落盘            |
| `buildCurrentSnapshot(series, extraSeasons)`         | 前端快照带上成员的季，否则它们永远被判成「有变化」                          |

`path` 加前缀是必要的：主系列与成员经常都有叫「正片」的季目录，不带来源时界面上两个选项一模一样，模型也无从判断。

## 验证

服务端单测（`test/server/bangumi-merge-scope.test.ts`，鸭子类型假对象，不碰真实媒体目录）：

- 主系列 + 成员的季按顺序拼接，成员季 `path` 为 `微速前行！ / 正片`，主系列保持 `正片`；
- 成员的季能写入标题与集标题，系列字段写主系列，成员的 `waitDataSave` 被调用；
- 不属于合并组的季仍然拒绝。

前端 CDP 实测（夹具拦截 `/data/*`，不触达真实 Bangumi 与模型）：匹配步骤列出 2 个季——`正片` 与 `微速前行！ / 正片`；预览步骤出现成员季分组，汇总为「将写入 4 项：系列字段 2 · 季标题 1 · 集标题 1」。

`buildKeywords` 补了 3 条用例（去重保序、成员标题参与、空值过滤）。全量 `vitest run` 通过。

## 影响面

- 未合并的系列行为不变（`mergeGroup` 直接返回单元素数组）。
- 系列字段（标题、简介、日期、状态、类型）仍然只写主系列，成员系列自身的标题不会被 Bangumi 的条目名覆盖。
- 写入失败仍整次中止：校验在任何写操作之前完成，跨系列也一样。
