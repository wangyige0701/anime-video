# 合并集的标题交给模型合并

- 日期：2026-11-28
- 模块：server
- 类型：功能

## 现象

本地把连续几集压成一个视频时（`01-03.mp4`、`04-06.mp4`），同步后标题只有首集的。第 2、3 集还被当成「本地缺集」，提示「官方 2 集在本地没有文件」。

## 方案

**不写规则判断合并**。文件的集号区间、要不要合并、合并成什么标题，全部交给模型，结果进预览由人工确认。后端只做两件事：决定什么时候值得问模型、校验模型输出。

### 提示词（`ALIGN_SYSTEM`）

集对齐本来就有一次模型调用，合并能力并入这一次，不新增请求：

- `map` 的值除单个 k 键、`null` 外，允许 k 键数组：`{"f1":["k1","k2","k3"]}` 表示这个文件装了连续几集。
- 新增 `titles`：数组值的文件要给出合并标题——保留各集要点、重复作品名只留一次、用「／」连接、不编造、≤80 字。
- 第 6 条写明「是否需要合并由你判断，拿不准按单集处理并写进 reason」，避免模型为凑数组强行合并。
- 顺手压掉了原有说明里的重复表述。`ALIGN_SYSTEM` 从 1851 字符降到 1734（-6%），功能是净增的。

### 触发条件（`runPreview`）

原有逻辑只在 `alignByRules()` 失败时调模型。合并集恰恰是「规则能对齐」的情况（`01-03` 解析成第 1 集），因此增加一个信号：**本地文件数少于官方正片集数**。合并必然减少文件数，这个条件一定能覆盖；文件数与集数一致时规则已能一一对应，不多花一次请求。

### 校验与预览

- `parseAlignResult()` 新增 `merged` / `titles`。数组里任一项不合法（不存在、已被占用、同一条目重复）→ 整个文件按无对应处理，不做部分采纳。标题非空且不超过 120 字才采纳，否则告警并退回该文件的首集标题。
- `PreviewEpisode` 新增 `coveredCount` / `coveredTitles`，前端据此在行内标「合并 N 集」，鼠标悬停列出覆盖的各集标题。
- 模型整季都返回 null 时视为无信息量，退回规则结果——否则会把整季标成「未匹配」。

## 验证

`test/server/bangumi-prompts.test.ts` 新增 3 例：数组值 + 标题采纳、合并但没给标题时告警、数组内重复指向同一集时整条作废。

`test/server/bangumi-merged-episodes.test.ts`（新增 4 例）：标题用模型结果且覆盖集数正确、没给标题时退回首集标题、模型整季 null 时退回规则、普通单集不受影响。

全量 `vitest run` 45 → 46 文件、440 → 447 例通过；服务端 `tsc`、前端 `vue-tsc` 无报错。

## 影响面

- 文件数与官方集数一致的季行为完全不变（不加请求、不加字段值）。
- 文件数偏少的季会多一次集对齐调用，这正是需要模型判断的场景。
- 写回语义不变：一个本地文件仍对应一条集记录，`position` 按文件顺序，覆盖的官方集只用于取标题。
