# 建立变更记录与模块文档规范

- 日期：2026-11-17
- 模块：shared
- 类型：文档
- 涉及模块：shared、web、server、hls、desktop（仅约定层面的覆盖）

## 背景

仓库此前只有根 `AGENTS.md` 与各子项目 `AGENTS.md`，它们描述“现在是什么样”，没有地方记录“某次改动为什么这样做”。

实际影响：

- 追溯某个行为（例如剧集顺序为何由 `sort` 字段而非文件名决定）只能靠读代码和猜历史。
- 多人或多次 Agent 会话之间没有交接信息，容易重复试错或推翻已经验证过的取舍。
- 子项目 `AGENTS.md` 越写越长，混杂了“约定”和“实现细节”，新人/Agent 难以快速定位。

## 目标与取舍

目标：

1. 每次改动都能留下可检索的“改了什么、为什么、怎么改、影响哪些文件”。
2. 长期有效的实现细节有独立落点，不挤占 `AGENTS.md`。
3. Agent 有固定阅读顺序，进入任何模块都能先拿到约束再动手。

取舍：

- **采用三层文档模型**（changes / modules / AGENTS.md）而不是在 `AGENTS.md` 里追加修改日志，避免“当前状态”和“历史流水”互相污染。
- **变更记录只增不改**，保证历史可回溯；错误用追加段落修正，不静默改结论。
- **要求同一次提交内写记录**，而不是事后补，避免记录与代码脱节。

## 实现要点

- `docs/changes/` 按子项目分目录，跨模块改动归入主导模块并在记录中列出全部涉及模块。
- `docs/modules/` 存放“当前有效”的模块细节，`AGENTS.md` 只留一句话摘要加链接，禁止两处重复维护。
- 变更记录模板固定六段：背景、目标与取舍、涉及文件、实现要点、行为变化与兼容性、验证。缺任何一段都视为不合格。
- 索引与记录同批维护，`INDEX.md` 是唯一入口。
- 提交纪律写入规范与根 `AGENTS.md`：改动分批提交（文档/单个功能/修复/依赖各自独立），完成一处可验证改动立即提交；单个功能的提交必须包含代码、变更记录、索引和 `AGENTS.md`/模块文档更新。

## 行为变化与兼容性

- 不改变任何运行时行为、接口与构建产物。
- 对开发者新增强制流程：改动分批提交并及时提交；改动代码时需同步写记录；`AGENTS.md` 的“文档同步要求”与“Git 提交说明规范”已更新，未写记录或未分批提交视为未完成。
- 历史改动不补写记录，从本次开始执行。

## 验证

- 人工复核：三层文档的职责描述互不重叠，且都指向唯一入口。
- 用一个真实改动（详情页剧集拖拽排序）试跑规范：记录、索引、模块文档、`AGENTS.md` 四处同步更新，验证流程可执行。
