# 开发规范新增测试用例强制要求

- 日期：2026-11-22
- 模块：shared
- 类型：文档
- 涉及模块：shared（根约定）、web

## 背景

此前的验证约定只要求类型检查、构建与手工验证，逻辑正确性依赖人工点检。首页过滤与排序这类纯计算一旦回归，手工很难覆盖全部分支（例如时间范围两端、无上线时间的条目、反向拖动）。

## 目标与取舍

把「功能实现必须同时补齐测试用例、边写边测」写成强制约定，明确测试放置位置、覆盖范围与提交前必须执行的命令，避免下次继续把测试留到最后或干脆不写。

取舍：不为前端引入组件测试框架（jsdom + @vue/test-utils）——当前需要测试的是过滤、排序、分组、换算这类纯逻辑，抽成纯函数后用现有 Vitest 即可覆盖；组件交互（拖拽、失焦提交、主题表现）继续走手工验证并写入变更记录，避免为了测试而引入一整套浏览器环境依赖。

## 实现要点

- 可复用判定规则优先抽成不依赖响应式与浏览器 API 的纯函数模块，测试直接传入普通对象。
- 前端纯逻辑测试放根目录 `test/web/`，与被测模块同名；服务端测试沿用现有 `test/`。
- 用例至少覆盖正常路径、空数据/缺失字段、边界值三类。
- 提交前执行 `pnpm exec vitest run`；无法自动化的部分在 `docs/changes/` 的「验证」段落写明手工验证方式与结果。
- 纯样式或文案改动可以不补测试，但要在变更记录里说明。

## 行为变化与兼容性

仅文档约定，不改变运行时代码与既有测试结构。现有 `test/config-parser.test.ts` 与新增的 `test/web/*.test.ts` 都在根 Vitest 的发现范围内。

## 验证

- `pnpm exec vitest run` 通过（含新增的前端用例），确认规范描述的命令可用。
- 手工确认 `test/web/` 下两个测试文件按规范命名并覆盖边界分支。
- 已知既有失败（本次未处理，与本次改动无关，需要单独修复）：
  - `web/test/keyboard/info.test.ts` 有 2 条用例仍按旧模板 `($key)` 断言，而实现已改为 ` ($key)`（带前导空格）；
  - `server/test/video.test.ts` 在根 Vitest 环境中缺少 `__APP_CONFIG__` 定义，属于测试环境配置缺口。
  在修复前执行 `pnpm exec vitest run` 整体为「失败」，需按文件名过滤或先修复上述两项。
