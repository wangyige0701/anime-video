# 新增本地调试配置初始化脚本

- 日期：2026-11-27
- 模块：shared
- 类型：功能
- 涉及模块：shared

## 背景

Bangumi 与 AI 接口的调试需要代理地址和密钥。项目原有的配置体系是 `config.yaml`，该文件受版本控制，写入密钥会直接进仓库；同时 `config-parser` 会把每个字段解析为 `{ value, comment }`，临时调试项塞进去会污染正式配置。

## 目标与取舍

用 `.env` 承载调试配置，`.env.example` 作为唯一模板：

- `.env.example` 入库，只含键名、注释和默认值，不含任何密钥。
- `.env` 由脚本生成，已被 `.gitignore` 忽略。
- 脚本每次按模板**整体重写** `.env`：模板保留的键沿用已有值，模板删除的键直接移除，不留注释。
- 若采用「已存在就跳过」的策略，模板新增键后需要手工补，容易与模板漂移；整体重写让模板始终是唯一事实来源。

代理语义：`BGM_PROXY` 与 `AI_PROXY` **互相独立，留空即直连**，不做继承。部分 AI 服务本身无需代理，继承会让请求绕一圈甚至失败。

## 涉及文件

| 文件                   | 改动                                       | 原因                       |
| ---------------------- | ------------------------------------------ | -------------------------- |
| `.env.example`         | 新增模板，声明 7 个键与说明                | 唯一事实来源，可入库       |
| `scripts/env.mjs`      | 解析、加载、必填断言、URL 校验             | 零依赖，供后续调试脚本复用 |
| `scripts/init-env.mjs` | 按模板重写 `.env`，提供 `--check`          | 初始化与自检分离           |
| `.gitignore`           | 忽略 `.env`、`.env.*`，放行 `.env.example` | 防止密钥误传               |

## 实现要点

- 优先级：进程环境变量 > `.env` > `.env.example` 默认值，便于临时覆盖而不改文件。
- 回填规则：模板键在旧 `.env` 中为非空值则沿用，空值回落到模板默认值；模板中不存在的键在重写后自然消失。
- `--check` 只输出「已填写 / 未填写 / 格式无效」，不打印任何值；必填项缺失时以退出码 1 结束，便于脚本串联。
- 写入采用 `临时文件 + rename`，避免中途失败留下半截配置。
- 脚本不读取、不打印、不上报 `.env` 内容；任何报错只报键名。
- 仅作为命令直接执行时运行，被测试导入时只导出纯函数（`renderEnv`）。

## 行为变化与兼容性

- 不影响现有 `config.yaml` 与 `__APP_CONFIG__`，运行时行为无变化。
- 新增脚本目录 `scripts/`，不参与 workspace 构建，也不进发布产物。
- 部署环境需要这些调试能力时，同样通过环境变量注入，不需要提交 `.env`。

## 验证

- `node scripts/init-env.mjs`：在隔离副本中验证三种情况——已填值沿用、模板新增键补默认、模板已删键被移除。
- `node scripts/init-env.mjs --check`：必填项齐全时退出码 0，缺失时 1，输出不含任何值。
- `git check-ignore -v .env`：确认 `.env` 已被忽略、`.env.example` 仍在版本控制内。
