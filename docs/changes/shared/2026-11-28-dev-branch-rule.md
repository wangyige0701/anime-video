# 新增开发分支强制规范

- 日期：2026-11-28
- 模块：shared
- 类型：文档

## 背景

此前只有提交说明与提交时机的规范，没有规定在哪个分支上提交。功能改动直接落在 `master` 会同时满足「可发布」与「开发中」两个互相冲突的要求，回退一个未完成的功能只能重写历史。

## 改动

根 `AGENTS.md` 新增「分支策略（强制）」章节，位于「Git 提交说明规范」之前：

- 所有功能开发在开发分支进行，`master` 只保留可发布状态；功能、缺陷修复、文档与规范、依赖升级都不例外。
- 默认只维护一个长期开发分支 `dev`，当前分支不对时先切回 `dev` 再开始改动。
- 仅当主要功能必须与 `dev` 上的在途改动隔离时才从 `dev` 切出 `feature/<主题>`，处理完合回 `dev` 并删除。
- 判断依据是「是否必须隔离」而不是「改动大不大」；多子项目的普通功能仍在 `dev` 上按批次提交。

## 落地

本次改动同时把仓库切到新建的本地分支 `dev`（自 `master` 切出），后续批次都在该分支提交。

## 验证

- `git branch --show-current` 输出 `dev`。
- 规范条目与既有「提交时机（强制）」不冲突：前者约束在哪个分支提交，后者约束何时提交。
