# 时间轴补满操作位、清除改为文字按钮并新增路由切换遮罩

- 日期：2026-11-22
- 模块：web
- 类型：样式 / 功能
- 涉及模块：web

## 背景

三处问题一起反馈：

1. **时间轴右侧缺一块没填充**。上一版为了避免轴宽跳动，给范围文案留了 86px 固定占位、选中后把文案设成 `opacity: 0`。结果选中状态下，轴右端到「清除」图标之间出现一大块没有任何刻度的空档，看起来像时间轴断了一截。
2. **清除按钮是图标**。`CircleClose` 图标只有 16×16，在 62px 高的过滤栏里不好点，也看不出是「清除时间筛选」还是「关闭面板」；样式上也没跟主题体系对齐。
3. **路由切换没有反馈**。视图按路由分包，详情页带着整块播放器代码（约 800KB）。首次进入时脚本要下载，这段时间页面停在旧视图上什么都不动，慢网速下会被当成「点了没反应」。
4. 另外首页月分割线太淡：线条用了 `d-3`（比背景更暗）、文字用了 `l-4`/`l-3`，在深色背景上几乎融进背景。

## 目标与取舍

1. 时间轴铺满内容区剩余宽度，右侧只留一个**固定 52px 的操作位**：未筛选放「全部时间」文字，筛选后换成「清除」文字按钮。两种状态宽度一致，轴不会被重新分格，也不会出现没有刻度的空档。
2. 清除按钮改为文字按钮，配色只用中性白描边 + 主题亮色文字 + `rgba(#fff, …)` 背景，五套主题都不需要单独覆盖。
3. 抽出 `components/common/GlobalLoading.vue` 作为唯一遮罩实现，新增 `router/loading.ts` 的 `loadingGuard`：导航开始计时 120ms 后才显示，`afterEach` / `onError` 立即收起。首屏数据加载与路由切换共用这一层，只换文案。
4. 分割线细线与两侧文字改用**亮于背景**的主题梯度：线条与数量 `l-5`、月份标题 `l-6`。

取舍：

- **不把范围文案放在轴内浮层**：轴右端叠文字会压住柱体，且与「贴着选区块」的气泡重复；未筛选时右侧本来就没有选区，把「全部时间」放操作位最自然。
- **不恢复 `visibility: hidden` 的图标按钮**：图标命中区太小，换成文字后按钮本身占 38px，操作位宽度可以定得更小（52px），比原来的 86 + 16 省下约 50px 给刻度。
- **遮罩加 120ms 延迟**：不加延迟时本地切换会闪一下白雾；延迟后只有真正卡在下载上才出现。
- **不按导航计数**：重定向会让原导航的 `afterEach` 不触发，计数容易只增不减；改成「后一次 `beforeEach` 重置定时器、任意结束就收起」，配合 `onError` 兜住分包失败。

## 验证

- 单元测试：`pnpm exec vitest run` —— 13 个文件 147 条全绿（新增 `route-loading.test.ts` 7 条）。
- `vue-tsc --build`、`vite build` 通过（入口 chunk 91.04KB / gzip 33.83KB）。
- 无头 Chrome 真实鼠标事件（真实片库，1600×1000）：
    1. 未筛选、选中、清除三种状态下 `.axis-host` 宽度均为 1040px，轴右端紧贴操作位（操作位 52px，清除按钮 38×18，「全部时间」文字 44px），没有空档；
    2. 点击「清除」后恢复「全部时间」，列表回到未过滤状态，轴宽不变；
    3. 分割线实测 `.line` 为 `rgb(176,160,255)`、`.label` 为 `rgb(189,176,255)`，4 倍放大截图确认细线清晰但比卡片标题弱；
    4. 路由遮罩：CDP 限速 120kbps + 禁用缓存后点卡片，180ms 左右出现「正在加载页面…」遮罩并覆盖整页，导航完成后自动收起；正常网速下两次实测为 207ms 出现 / 431ms 收起、181ms / 742ms，不出现卡住；
    5. 首屏遮罩：用 `Fetch.enable` 卡住 `/data/series`，遮罩文案为「正在加载视频数据…」，放行后正常消失。
