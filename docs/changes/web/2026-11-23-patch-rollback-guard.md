# 乐观更新失败回滚不再覆盖并发编辑的新值

- 日期：2026-11-23
- 模块：web
- 类型：修复

## 背景

`web/src/data/common.ts` 的 `patchField()` 是三类对象所有字段更新的公共实现。它沿用原先逐字段手写代码的行为：先记下旧值、写入乐观值，请求失败时无条件恢复旧值。

同一字段的请求使用 `axios-useful` 的 `Single.PREV` 策略（保留新请求、取消旧请求），因此快速连续编辑时前一次请求会以取消异常失败。此时 `patchField()` 的 `catch` 会把本地值回滚成**比当前界面更旧**的值：

1. 用户改成 A：本地 A，请求 A 发出。
2. 用户改成 B：本地 B，请求 B 发出，请求 A 被取消。
3. 请求 A 的 catch 执行：本地被写回初始值，界面短暂回退。
4. 若请求 B 的完成顺序在 A 的 catch 之前，本地会**停在初始值**，与已落库的 B 不一致，直到刷新页面。

## 目标与取舍

- 回滚只在「本地值仍是本次乐观写入的值」时执行，即失败只撤销自己那次改动。
- `settle`（服务端返回值纠正本地值）同样加同样的守卫：请求期间用户又改了值，就不能用旧响应覆盖新值。
- 不改动状态控制器（`on/off`）语义，也不引入请求序号/取消令牌等额外机制——问题根源是回滚条件，不是并发控制。

## 实现要点

守卫不能用传入的 `next` 做比较：`ref<string[]>` / `ref<object>` 读取时返回的是 Vue 的响应式代理，与写入的原始数组不是同一个引用，直接比较会让所有数组字段的回滚失效。因此以「写入后立刻读回的值」作为标记：

```ts
target.value = next;
const optimistic = target.value; // 数组/对象这里是响应式代理
// 失败时：只有本地值仍是 optimistic 才回滚
```

`settle` 的守卫同理：服务端返回的默认标题只覆盖自己那次乐观值。

## 行为变化与兼容性

- 无并发编辑时行为完全不变：成功保留乐观值（或被 `settle` 覆盖），失败回滚。
- 并发编辑时，前一次失败的请求不再影响后一次的结果。
- 无接口、DTO、持久化数据变化。

## 验证

- `pnpm exec vitest run`：19 文件、186 用例全部通过（新增 2 例）。
- 反向验证：去掉守卫后新用例「同一字段前一次请求失败时，不回滚后一次已写入的值」失败，确认用例有效。
- 数组字段用例覆盖「代理引用不影响回滚」这一点：失败回滚、成功保留都断言。
