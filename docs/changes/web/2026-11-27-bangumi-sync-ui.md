# 详情页新增 Bangumi 同步入口与预览确认

- 日期：2026-11-27
- 模块：web
- 类型：功能

## 背景

服务端已经提供 `match` / `preview` / `apply` 三段接口，但只能靠命令行脚本调用。同步过程中「哪个季对哪个条目」「这一集对应官方第几话」都需要人工判断，必须在写入前让人看到完整的变更清单并逐项确认，否则错误数据会直接落进 `.video.json`。

## 目标与取舍

- 入口放在详情页标题行右侧：同步的对象是「当前系列」，与页面上下文一致，也不占用元数据行的三列布局。
- 对话框分两步：先确认季与条目的对应（可改 AI 建议），再确认将要写入的字段、标题与顺序。`apply` 只在第二步确认后调用一次。
- 前端只做「展示 + 收集勾选」，所有推断都由服务端完成：前端不解析文件名、不猜集数、不重排，只把预览结果按顺序拼成 `order` 数组。
- 可测逻辑全部放在 `utils/bangumiSync.ts`（纯函数，15 个用例），组件只负责把状态接到这些函数上。

## 实现要点

1. **季顺序**：`orderSeasonsBySuggestion()` 按 AI 返回的 `order` 稳定排序，缺失时按本地下标参与比较。排序必须稳定，否则同一份输入两次渲染的顺序不同，用户确认的季与提交的季会对不上。服务端仍会按条目首播日期决定季内顺序，这里只影响请求里的季排列。
2. **默认勾选**：空标题、空描述、无日期、无类型、无状态的字段一律不勾——服务端把「描述传空串」当作清空，默认全选会把 Bangumi 缺失的数据写成清空本地数据。标题为空的集同样默认不勾。
3. **重排单独成项**：`order` 必须是该季全部集的一个排列，无法按集部分勾选，因此在季一级提供「按预览顺序重排 N 集」一个开关，只有一集时默认关闭。
4. **未勾选的季整体跳过**：`buildApplyInput()` 在季的三项都为空时不把该季放进 `seasons`，避免发无意义的写请求；`summarizeSelection()` 的 `total` 为 0 时提交按钮禁用。
5. **写入后整体替换**：`apply` 成功后调用 `refreshSeries()` 重新扫描装配，把新的 `Series` 实例通过 `applied` 事件交给详情页整体替换。标题、排序、季与集都可能变化，逐字段打补丁容易和缓存中的旧对象混淆。
6. **失败保留现场**：`apply` 失败不关闭对话框，勾选状态保留，便于调整后重试；`match` 失败则收起对话框（请求失败的提示由 `api.ts` 拦截器统一给出，组件不重复提示）。
7. **深色主题**：对话框与下拉面板都挂载在 `body` 上，样式写在非 scoped 块里，颜色全部通过 `map.get(token.$theme, ...)` 与 `--el-*` 变量覆盖，没有硬编码主题色。

## 行为变化与兼容性

- 纯前端新增：不改动服务端接口、数据文件结构与既有编辑入口（标题、描述、日期、状态、类型、拖拽排序）。
- 对话框内展示的「修改前」取自当前领域对象，与页面其他位置显示的值一致。
