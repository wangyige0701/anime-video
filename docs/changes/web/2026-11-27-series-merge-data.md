# 前端合并关系数据层与列表过滤

- 日期：2026-11-27
- 模块：web
- 类型：功能
- 涉及模块：web

## 背景

服务端已经能保存「主系列 + 成员」的合并关系，前端需要三件事：把 `mergedIds` 读进领域对象、能发起合并与脱离、列表不再展示被合并的系列。

## 涉及文件

| 文件                                     | 改动                                                                |
| ---------------------------------------- | ------------------------------------------------------------------- |
| `web/src/api/series.ts`                  | `mergeSeries()`、`detachSeries()`                                   |
| `web/src/data/series.ts`                 | `mergedIds` 字段、`mergeMember()`、`detachMember()`、查询时排除成员 |
| `web/src/utils/seriesMerge.ts`           | 成员索引、可见性过滤、叠层计算、可合并判定（纯函数）                |
| `web/src/components/index/IndexList.vue` | 刷新管线同样剔除成员                                                |
| `test/web/series-merge.test.ts`          | 16 个用例                                                           |

## 实现要点

1. **`mergedIds` 用 `ref<string[]>` 保存**，页面的 `computed` 读取它会自动追踪，合并/脱离后不需要强制刷新整个列表就能更新叠层。
2. **`mergeMember()` 同步两个实例**：服务端合并会同时改主系列（追加）与被并入系列（清空），如果只更新主系列，被并入系列在缓存里仍然带着自己的旧成员列表，后续操作会读到过期数据。
3. **两处过滤点**：`querySeries()` 覆盖首屏与翻页，`IndexList` 的刷新事件覆盖全量刷新。两处都必须过滤，否则合并刚完成就会被刷新事件把成员塞回列表。过滤放在分页之前，避免每页空出坑位。
4. **悬空引用不报错**：`getGroupMembers()` 跳过找不到的 id。磁盘上的成员被删除时，服务端规范化会在下次扫描清理，但页面不能因为一条悬空引用整块渲染失败。
5. **叠层上限只影响展示**：`getMergeStack()` 最多返回 3 张首图，额外成员只体现在 `overflow` 数字上，不限制实际合并数量。

## 可合并判定

`getMergeRejection()` 返回拒绝原因，`null` 表示允许：

| 场景             | 结果                           |
| ---------------- | ------------------------------ |
| 拖到自己身上     | 不能合并到自身                 |
| 目标已在自己组内 | 该系列已在合并组中             |
| 目标是别人的成员 | 该系列已被合并，不能作为主系列 |
| 自己已被合并     | 该系列已被合并，请先脱离       |

与服务端校验规则保持一致，前端先行拦截只是为了在拖拽过程中给出即时反馈，不作为安全边界。

## 行为变化与兼容性

- 首页与搜索结果不再显示被合并的系列；未建立任何合并关系时行为与之前完全一致。
- `Series` 构造时对 `mergedIds` 做数组兜底，旧版本接口返回缺字段也不会让叠层计算崩溃。
- 纯新增文件与新增方法，未改动既有字段读写路径。
