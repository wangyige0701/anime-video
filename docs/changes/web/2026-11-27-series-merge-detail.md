# 详情页展示被合并系列的季

- 日期：2026-11-27
- 模块：web
- 类型：功能
- 涉及模块：web

## 背景

首页把 B 并入 A 之后，B 不再作为独立条目出现，它的季如果没有别的地方可看，内容就"消失"了。本次让主系列详情页把成员的季拼接进来，合并才真正等于"一个作品一个入口"。

## 涉及文件

| 文件                                         | 改动                                       |
| -------------------------------------------- | ------------------------------------------ |
| `web/src/views/[seriesId]/[name].vue`        | 拉取成员系列、拼接季列表、合并态禁用季拖拽 |
| `web/src/components/detail/DetailSeason.vue` | `groupTitle` 来源标签、`sortable` 开关     |

## 实现要点

1. **拼接顺序**：主系列自己的季在前，成员系列按 `mergedIds` 记录的顺序依次追加。顺序完全由主系列决定，不受加载完成先后影响。
2. **不做数据搬迁**：合并只是展示层聚合。季仍然归属各自的系列，季标题编辑、集排序、播放路径全部走原系列的接口与目录，不需要把季移到主系列目录下。
3. **来源标注**：只有成员系列的季带「来源系列」标签，主系列自己的季不标注——每项都挂一个标签反而更难扫读。
4. **合并态不提供季拖拽**：季排序接口的语义是「在所属系列内移动到第 N 位」，跨系列的季无法用这个语义表达。合并状态下隐藏手柄，`commitSeasonSort()` 也加了同名守卫；非合并系列的行为与之前完全一致。
5. **悬空成员跳过**：单个成员请求失败只跳过该成员，不让一条失效引用把整页拖垮（服务端的规范化会在下次扫描清理悬空 id）。
6. **默认展开**：主系列可能没有任何季（季都在成员目录里），默认展开项取拼接后的第一项，而不是 `series.seasons[0]`。
7. **Bangumi 写入后重算**：写入会改变季结构，`handleApplied()` 替换实例后重新拉取成员季。

## 行为变化与兼容性

- 未合并的系列：季列表、拖拽手柄、排序行为与之前完全一致。
- 合并后的系列：季列表变长、成员季带来源标签、季手柄隐藏；集级拖拽与播放不受影响。
- Bangumi 同步仍然只作用于主系列自身的季——成员的季不在它的 `changeSet` 里，这是合并语义带来的既有边界，已在模块文档中注明。
