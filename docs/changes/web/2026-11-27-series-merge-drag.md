# 首页拖拽合并与叠层展示

- 日期：2026-11-27
- 模块：web
- 类型：功能
- 涉及模块：web

## 背景

合并关系与服务端接口已就绪（见 `2026-11-27-series-merge-data.md`、`2026-11-27-series-merge-api.md`），本次补齐交互：

- 首页把一张系列卡片拖到另一张上，松手即把前者并入后者（后者为主系列）
- 主卡片背后叠出被合并系列的首图，最多三层
- 角标点开是成员面板，可逐个「脱离」

## 交互与实现

1. **阈值与点击共存**：卡片主体仍是 `router-link`。按下后移动超过 6px 才进入拖拽，否则照常跳转；拖拽一旦激活，松手时浏览器补发的 `click` 会在捕获阶段被拦掉，不会误跳详情页。
2. **翻转**：浮层是双面卡片，拿起时 `rotateY(180deg)` 从海报翻到标题面。翻转类名必须在浮层挂载后的下一帧才加上——挂载即终态时浏览器没有起始值可插值，动画不会执行。
3. **边缘自动滚动**：指针进入滚动容器上下 90px 内按距离线性加速滚动，单帧上限 26px，避免指针略微越界就飞速滚动。
4. **拖拽期间滚动加载**：滚到底后复用列表已有的 `endReached` 通道请求下一页（500ms 节流），不需要为拖拽单独实现分页。实测 40 → 42 张卡片，滚到底即触发。
5. **命中检测**：浮层 `pointer-events: none`，`elementFromPoint` 命中的永远是卡片；合法性交给 `getMergeRejection()`，非法目标直接不显示落点反馈。
6. **落点反馈**：目标卡片出现虚线框、海报轻微呼吸，并从左上滑出一层半透明「待合并」层，表达「松手后会叠进这里」。
7. **飞入动画**：松手后浮层移到目标中心、缩到 0.55 并淡出，同时发起合并请求，两者都结束才收尾——请求通常快于 260ms 的动画，若直接 `finally` 收尾，浮层会在飞入途中被抹掉。
8. **叠层**：横向偏移 8/16/24px、纵向 6/12/18px，横向多、纵向少，因为纵向偏移过大会压到上一行的标题；每层加 1px 亮描边，否则多张压暗的海报叠在一起看不出层数。三层上限只影响展示，超出数量体现在角标数字上。
9. **成员面板**：`el-popover` 按 `popper-class` 覆盖成深色（沿用详情页弹层的做法），成员行是封面 + 标题 + 脱离按钮，脱离后成员卡片立即回到列表。
10. **监听器统一交给 `@vueuse/core`**：`useEventListener` 在作用域内一次性注册、随作用域销毁解绑，处理器用 `pointerId` 判断是否处于一次按下中；帧循环用 `useRafFn`，`resume()` / `pause()` 控制启停。不需要手工维护挂载-卸载配对。

## 踩到的坑

**原生图片拖拽**：卡片海报是原生 `<img>`，按下后移动会先触发浏览器的图片拖拽，之后 `pointermove` 全部丢失，表现是「卡片拿起来就不动了」。修复是双保险：CSS 关掉 `-webkit-user-drag`，并在按下期间于捕获阶段拦截 `dragstart`。

## 行为变化与兼容性

- 未建立合并关系时，卡片结构与交互与之前一致（叠层不渲染、角标不渲染）。
- 合并/脱离后会广播全量列表刷新（复用既有 `refreshEmitter`），成员从列表消失或回归，主卡片位置随排序重排。
- 触摸设备不参与拖拽（按下即拖会抢走页面滚动），列表滚动与点击不受影响。
- `getSeriesCoverUrl()` 在没有首图时返回空串，不再拼一个必然 404 的空路径。
