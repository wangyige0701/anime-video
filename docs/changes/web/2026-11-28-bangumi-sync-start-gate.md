# 同步面板打开后不自动检索

- 日期：2026-11-28
- 模块：web
- 类型：优化

## 现象

点「同步 Bangumi」后，对话框一打开就发 `match` 请求。检索会访问 Bangumi、还可能调用模型，用户只是想看一眼或者点错了也会产生一次完整调用。

## 修复

对话框增加一个「未开始」状态：

- `SyncDialog` 不再在 `onMounted` 里调 `loadMatch()`；
- 未开始时显示说明页：要检索的系列名、本地季数、包含哪些合并系列、以及「检索与预览都不会改动数据」；
- 页脚由 `describeSyncFooter()` 的 `started: false` 分支给出，只有「取消 / 开始同步」；
- 点「开始同步」才把 `started` 置真并调用 `match`，之后进入原来的两步流程；
- 步骤条在未开始时两步都保持灰色，不假装第一步已经开始。

说明页的季数直接取快照里的季数，合并信息来自入口传入的 `mergedTitles`——入口在打开对话框前已经为快照加载过一次成员，这里不额外发请求。

## 验证

CDP 实测（夹具拦截 `/data/*`）：

```
打开面板          match 调用 0 次，页脚「取消 / 开始同步」，步骤条两步均未激活
点「开始同步」     match 调用 1 次，进入匹配步骤，页脚换成「取消 / 重新匹配 / 生成预览」
点「生成预览」     preview 调用 1 次，进入确认步骤
```

说明文案实测为「本地共 2 个季，含合并系列 微速前行！」。

单测：`describeSyncFooter` 补两条——未开始时只给「取消 / 开始同步」且取消可用；开始后换成匹配步骤那一组。

`type-check`、`build`、`check-vue-tags`、`vitest run` 通过。

## 影响面

- 只影响同步面板的入口时机，`match / preview / apply` 的请求与数据不变。
- 说明页占用一次首屏高度，对话框初始比之前高一点（内容约 3 行）。
