# Bangumi 同步面板

详情页标题旁的「同步 Bangumi」按钮打开的两步面板：先把本地季对上 Bangumi 条目，再逐项确认要写入的内容。**对齐规则与数据来源全在服务端**（`server/src/integrations/bangumi/`），前端只负责展示、勾选与提交。

## 1. 职责边界

| 层                                                      | 负责                                              | 不负责             |
| ------------------------------------------------------- | ------------------------------------------------- | ------------------ |
| `server/src/integrations/bangumi/`                      | 搜索条目、规则+AI 对齐剧集、生成预览结构          | 勾选状态、提交范围 |
| `web/src/utils/bangumiSync.ts`                          | 默认勾选、预览 → 提交入参、**差异对比**、数量统计 | 请求、DOM          |
| `web/src/components/detail/BangumiSync.vue`             | 入口按钮、打开对话框、写入后刷新                  | 面板结构、对齐规则 |
| `web/src/components/detail/bangumi-sync/SyncDialog.vue` | 步骤条、页脚按钮、关闭守卫                        | 差异规则、字段校验 |
| `…/MatchStep.vue`、`…/PreviewStep.vue`                  | 两步各自的展示与勾选回调                          | 请求、提交结构     |
| `…/useBangumiSync.ts`                                   | 三段请求、勾选状态、派生状态                      | DOM、样式          |

面板通过 `utils/dialog` 的 `openDialog()` 打开（见 `docs/modules/web/dialog.md`）：入口 `await` 它拿写入数量，取消时 Promise reject，入口不需要维护任何「是否打开」的状态。对话框内容跑在独立应用里，所以系列数据在打开时由 `buildCurrentSnapshot()` 压成快照传入。

**打开面板不会检索**：`match` 要请求 Bangumi、还可能调用模型，所以先显示一页说明（本次检索的系列、季数、包含哪些合并系列），点页脚的「开始同步」才真正发请求。这一步由 `describeSyncFooter()` 的 `started` 控制，`SyncDialog` 不再在 `onMounted` 里自动调 `loadMatch()`。

## 2. 两步流程

| 步骤 | 面板内容                     | 主要接口                                            |
| ---- | ---------------------------- | --------------------------------------------------- |
| 0    | 每个本地季一行候选条目多选   | `POST /series/:id/bangumi/match`                    |
| 1    | 系列字段与逐集标题的差异确认 | `POST /series/:id/bangumi/preview` → `POST …/apply` |

`match` 与 `preview` 都可能跑十几秒（上游 Bangumi 串行请求 + 模型对齐）。第二步的勾选只存在于前端，`apply` 一次提交全部选中项。

## 3. 差异对比（`diffPreview`）

「与当前完全相同」的项**不勾选、禁用勾选框、不计入「应用 N 项」**。避免把没有变化的字段重复写一遍。

| 字段        | 判为相同的条件                                |
| ----------- | --------------------------------------------- |
| 标题 / 描述 | 折叠连续空白并 trim 后逐字相等                |
| 上线时间    | 年、月都相等                                  |
| 状态        | 预览状态非 0 且与当前相等                     |
| 类型        | 集合相等（与顺序无关）                        |
| 季标题      | 与预览里的 `fromTitle` 相等                   |
| 重排        | 预览的 episodeId 序列与当前逐位相等           |
| 集标题      | 该集的 `episodeId` 在当前季里能查到且标题相等 |

两条必须记住的规则：

- **`same` 语义而不是 `changed`**。返回 `true` 表示「一致」。UI 里 `:disabled="same"` 不用取反，不容易写反。
- **预览缺字段一律判为「不同」**。空标题、无日期、空类型不会被当成「已一致」，否则「缺失」会被误认为「已经同步过」。这类项由 `createSelection` 的另一条规则处理：内容为空时默认不勾。两条规则叠加，空字段不会被勾也不会被禁用得很奇怪。

对比用的本地快照由 `buildCurrentSnapshot()` 在打开对话框时装配，只取会被覆盖的字段；季内顺序取当前展示顺序，否则用户改了排序却没同步时会永远判为「一致」。快照是普通数据而不是领域对象，对话框卸载后也不会有视图被异步结果写脏。

**快照必须带上被合并系列的季**（第二个参数）：服务端的同步范围是「主系列 + 成员」，少一组季会让成员的季被永远判成「有变化」，默认全选里也就混进了本来一致的项。

## 4. 布局约束

- **剧集列表必须纵向单列、每项两行**（标题一行、文件名一行）。标题与文件名都可能几十个字，横向并排时 `grid-template-columns: repeat(2, 1fr)` 的 `1fr` 等价于 `minmax(auto, 1fr)`，`auto` 下限会被最长不可断词撑开，整列溢出对话框——这是「横向布局把宽度撑开」的真实原因。改成纵向单列后不存在这个问题，也不必给每个 `1fr` 补 `minmax(0, 1fr)`。
- 标题、文件名都用 `nowrap + ellipsis + title` 属性：面板宽度固定，换行会把列表撑得很高，完整内容用悬浮提示看。
- **描述必须完整多行展示**，不截断、不做 JS 截断。`white-space: pre-wrap` 保留 Bangumi 原文的分段，`overflow-wrap: anywhere` 防止长串撑破容器。多行文本不加删除线（整段划线会盖住字），改由「当前 / Bangumi」两行标签区分。
- **一致与替换用语义色 + 文字，不用胶囊标签**：行尾是「圆点 + 保持当前值（绿）/ 将替换（红）」，一屏里连排十几个色块会很吵。绿色与设置页「已配置」同色值 `#8fd67a`，红色取低饱和 `#ff8f8f`，深色面板上不刺眼。
- 一致的字段只显示一份值；要替换的字段是「旧值 → 新值」，**旧值只压暗、不划删除线**（整行划线难读），方向由箭头和新值的提亮表达。
- **不要给每行加左侧色条**：剧集列表一屏几十行，重复竖线是最容易造成视觉疲劳的装饰。变化行只用浅底色（`d-3`）和状态文字区分。
- 剧集行：变化项在标题下多一行「原集标题」；无变化的集整行压暗（标题 `l-6`、序号 `l-4`），不加任何标签。

## 5. 请求期间禁止关闭

`busy = matching || previewing || applying`，期间：

- 内容组件调 `dialog.unclosable()`：同时关掉右上角按钮、Esc 与点击遮罩；结束后 `closable()` 恢复成打开时声明的值；
- 「取消」「上一步」由 `describeSyncFooter()` 统一置为禁用；
- 点击遮罩关闭本来就是关的（`closeOnClickModal: false`）。

原因是匹配/预览的响应要写回面板状态，关掉之后再返回等于往已卸载的视图里写数据：用户看不到结果，也不知道到底成功没有，只能重开一次。

**匹配失败时不要自动关面板。** 之前 `loadMatch` 的 `catch` 里写 `visible = false`，网络抖动会直接吞掉整个交互；现在保持打开，显示空态提示，用户可以就地「重新匹配」，不用回入口按钮重来。

## 6. 已知限制

- 只有一集的季不提供「重排」（无意义），预览顺序也不会被提交。
- 合并组内的季在界面上只能靠 `path` 前缀区分（同名的「正片」很常见），没有独立的分组标题。
- 季标题与集标题的「当前值」依赖前端领域对象的缓存。若在别处改了标题又没刷新页面，对比结果会偏保守（显示为有变化），不会漏改。
- 描述对比忽略首尾与连续空白，但**不做**标点、全半角归一化：这些差异落库后确实不同，应当让用户看到。

## 7. 验证方式

```bash
pnpm exec vitest run test/web/bangumi-sync.test.ts   # 对比 / 勾选 / 入参 / 快照 / 页脚按钮
pnpm --filter web type-check
pnpm --filter web build-only
```

面板类改动还要用 CDP 实测（`.cache/sync-confirm-check.mjs` 用固定夹具拦截 `/data/*`，不需要真实后端）：

- 步骤条当前步骤是主色描边 + 内点，不是纯白实心；
- `.episodes` 的 `scrollWidth === clientWidth`，页面无横向溢出；
- 描述的 `.long-text` `white-space: pre-wrap` 且 `scrollHeight === clientHeight`（没有被裁）；
- 请求进行中右上角关闭按钮数量为 0、Esc 与遮罩都无效；请求结束后 Esc 能关；
- 断网打开面板 → 匹配失败后面板仍在，提示只有一条中文；
- 关闭后 `body` 下不再有 `.el-dialog` / `.el-overlay`，连续打开两次不会叠出两个对话框。
