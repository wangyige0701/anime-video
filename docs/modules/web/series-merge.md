# 系列合并（展示层聚合）

## 1. 职责边界

合并把同一部作品散落在多个目录里的系列聚合成一个入口：

- 首页把一张卡片拖到另一张上，松手即把前者并入后者，后者成为**主系列**；
- 主系列卡片背后按成员顺序叠出首图，角标点开是成员面板，可逐个「脱离」；
- 主系列详情页把自己的季与被合并系列的季拼在一起展示。

不负责的事情：**不搬迁文件、不搬迁季**。季仍归属各自的系列，标题编辑、集排序、播放路径全部走原系列，因此磁盘布局与已有数据完全不变。

## 2. 数据模型

合并关系只保存在主系列的 `mergedIds`（有序数组）上，被合并系列不保存反向引用。

```jsonc
// 主系列
{ "id": "A", "mergedIds": ["B", "C"] }
// 被合并系列
{ "id": "B", "mergedIds": [] }
```

三条不变式（服务端 `normalizeMergeGroups()` 在每次全量扫描后收敛）：

1. 成员必须存在、不能是自己、同一列表内不重复；
2. 一个系列最多属于一个主系列，被多个主系列声明时**先到先得**；
3. 不允许链式合并：被合并系列的成员会**展平**转移给新的主系列，它自己的列表清空。

第 3 条同时让「A 持有 B、B 持有 A」这类成环数据自然消解为各自独立，不需要额外的成环检测。

数组顺序既是叠层顺序，也是详情页季分组的拼接顺序，所以它是**语义数据**，不要排序或去重后丢失顺序。

## 3. 交互状态机

`web/src/components/index/useSeriesDrag.ts` 维护四个阶段：

| 阶段     | 触发                    | 表现                                     |
| -------- | ----------------------- | ---------------------------------------- |
| `idle`   | 初始 / 收尾             | 无浮层                                   |
| `drag`   | 按下后移动超过 6px      | 浮层翻面跟随指针，逐帧自动滚动与命中检测 |
| `drop`   | 在合法目标上松手        | 飞向目标中心、缩小淡出，同时发起合并请求 |
| `return` | Escape / 松开时没有目标 | 飞回原位置                               |

阶段切换的唯一入口是 `begin()`（pointerdown 记录候选）、`activate()`、`onPointerUp()`、`cancel()`、`reset()`。新增行为请挂在这些入口上，不要在模板里直接改 `state.phase`。

浮层的两个面都显示封面：正面是纯海报，背面是同一张海报加底部渐变遮罩与标题。翻面只是为了同时看到「拖的是哪一部」的名称，**不能把它换成一张纯色卡片**——那等于在拖拽时把最有辨识度的信息藏起来。没有封面的系列两面都用标题占位。

## 4. 关键约束

- **阈值与点击共存**：卡片主体仍是 `router-link`，移动不足 6px 视为点击；拖拽一旦激活，松手时补发的 `click` 会在捕获阶段被拦掉，否则会误跳详情页。
- **原生图片拖拽必须拦掉**：海报是原生 `<img>`，按下后移动会先触发浏览器图片拖拽，之后 `pointermove` 全部丢失（表现为「拿起来就不动」）。CSS 关掉 `-webkit-user-drag` 并在按下期间捕获阶段拦截 `dragstart`，两道都需要——前者防止起拖，后者兜底其它入口。
- **翻转类名要延后一帧**：浮层挂载即终态时浏览器没有起始值可插值，动画不会执行。
- **背面不能丢封面**：背面用内联 `background-image` 沿用正面海报，再叠 `::before` 渐变遮罩保证底部标题可读；两面都设了底色兜底，否则无封面时浮层会变成透明的一层。
- **滚动加载复用现有通道**：滚到底后 emit 既有 `endReached` 事件（500ms 节流），不要为拖拽单独写分页。
- **命中检测依赖 `pointer-events: none`**：浮层及其子元素必须穿透，`elementFromPoint` 才会返回卡片。
- **合法性以服务端规则为准**：前端用 `getMergeRejection()` 先拦一遍，只是为了让无效目标不显示落点反馈，不作为安全边界。
- **监听器与帧循环交给 VueUse**：`useEventListener` / `useRafFn` 随作用域销毁自动解绑，处理器用 `pointerId === -1` 判断是否处于一次按下中，不要手工维护挂载-卸载配对。
- **叠层上限只影响展示**：卡片只画 3 层（`MERGE_STACK_LIMIT`），超出的数量只体现在角标数字上，合并数量本身不受限制。
- **封面与叠层取的是最终顺序，不是各自的 `images[0]`**：`getMergeCovers(main, members)` 返回三个值——`cover` 为整组（主系列 + 全部成员）在最终顺序里的第一张，可能属于任何一个成员；`covers` 为成员 id → 该系列在最终顺序里的首图；`stack` 为叠层路径，**排除封面来源系列**，主系列排在最前。详情页换了首图，列表页必须同时改变，否则用户会以为排序没保存。
- **封面已经占掉的系列不能再进叠层**：两个系列合并、把成员图拖到首位时，卡片本体显示的是成员图，叠层只剩主系列一张；若照旧按 `mergedIds` 取成员首图，同一张海报会在本体与叠层各出现一次。

## 4.1 角标与卡片悬停

角标是唯一能看出「这个卡片其实是一组」的入口，所以要同时解决「看得懂」和「点得到」：

- **图标 + 数字**：只给数字看不出含义，用 `Files` 图标表达「多份」；
- **悬停原地展开**：`max-width` 从数字宽度过渡到文字宽度，显示「已合并 N 个系列」，同时隐藏数字避免重复。不用 `el-tooltip`——它套在 `el-popover` 的 reference 里会吃掉 click，成员面板打不开（实测 `visible: false`）；也不用自绘浮层，角标贴着卡片右缘，浮层向左会溢出卡片、压到相邻项；
- **面板打开期间钉住展开态**：展开态有两个来源——`&:hover` 与 `.is-pinned`（由 `v-model:visible` 的 `panelVisible` 驱动）。成员面板是 teleport 到 body 的独立弹层，指针移进面板后角标就收不到 hover，若只靠 `:hover`，用户还在看面板、角标却缩回数字。关闭面板时 `panelVisible` 归 false，指针若已不在角标上就正常收回；
- **角标底色比主题色提亮一档**（`color-mix(var(--theme) 86%, #fff)`）：深蓝、深绿主题的 `primary` 与海报同族，纯主题色会糊进图里；
- **三层边界**：深色外描边压轮廓、投影拉开距离、内侧白高光做凸起，这样在海报明暗不可控时都能辨认；
- **窄屏兜底**：`max-width: calc(100% - 12px)` + 文字 `ellipsis`，展开时不顶出海报。

卡片悬停原来是三层 `l-5 / l-9` 模糊阴影，在暗色主题下就是一圈白色光晕，海报边界被糊掉。现在改成：

```scss
box-shadow:
	0 0 0 1px map.get(token.$theme, 'l-6'),
	// 主题提亮两档的细边，勾出边界
	0 16px 32px -12px rgba(0, 0, 0, 0.75); // 中性深投影，只负责浮起
```

描边必须取 `l-6` 而不是 `primary`：深蓝、深绿主题的 `primary` 与页面底色几乎同色，半透明后完全看不出边界。同时主图上浮 2px、标题 `l-8 → l-9`、叠层再退开 3px，**不使用任何白色发光**。拖拽落点的 `0 0 18px 2px l-5` 同样换成了中性深投影。

## 5. 详情页的季与图片拼接与跨系列排序

`web/src/views/[seriesId]/[name].vue` 在拿到主系列后并行拉取各成员的季与图片：

- 默认顺序：主系列自己的季在前，成员按 `mergedIds` 顺序追加；再应用主系列记录的**显式顺序** `mergedSeasonOrder`，最终顺序由 `orderMergedSeasons()` 给出；
- 图片同理：`orderMergedImages()` 先拼默认顺序，再应用 `mergedImageOrder`，重复路径去重且保留首次出现；
- **成员未就位时不能按已加载的部分算**：`orderDisplayImages(pending)` 在成员请求返回前直接用 `mergedImageOrder` 占位。否则首帧只有主系列图片，算出的首图是主系列第一张，成员到达后再纠正会跳一次；
- 成员季带「来源系列」标签，主系列自己的季不标注；
- 单个成员加载失败只跳过该成员，不让一条悬空引用拖垮整页。

**跨系列拖拽**：季手柄在合并状态下同样提供，`commitSeasonSort()` 按是否合并分流——单系列提交「移动到第 N 位」，合并组提交完整顺序给 `PUT /data/series/:id/merge/seasons`。服务端把各系列自己的 `sort` 重编为该顺序中的子序，前端随后 `syncGroupSeasons()` / `syncGroupImages()` 把全局顺序拆回主系列与每个成员（`syncSort()` + `setSeasons()` / `syncImages()`）。

这一步不只是本地对齐，它保证下面这条不变式：**合并期间每个系列看到的子序，就是脱离合并后该系列自己的顺序**——包括刷新页面、重新扫描磁盘之后。合并只发生在展示层，`images` 与各系列的 `sort` 都没有被跨系列「合并」掉。

**图片排序面板**：海报右上角的入口（多图才出现）打开 `DetailImageManage.vue`，缩略图网格拖拽调整顺序后保存。面板只做拖拽与保存，写入通过 `commit` 回调交给详情页：面板挂在独立应用里，拿不到详情页的 provide，也不该判断合并组走哪个接口。

服务端字段语义、端点与「脱离后顺序保持」的验证见 [docs/changes/server/2026-11-28-merge-group-order.md](../../changes/server/2026-11-28-merge-group-order.md) 与根 `server/AGENTS.md` 的「合并组的跨系列排序」。

## 6. 已知限制

- **触摸设备不支持拖拽**：按下即拖会抢走页面滚动。列表滚动与点击正常，合并需要鼠标或手写笔。
- **成员不能直接被拖走**：成员卡片不出现在列表里，要换组必须先「脱离」再拖。
- **Bangumi 同步只覆盖主系列自身的季**：成员的季不在默认的 `changeSet` 里。
- **页数固定**：首页分页在合并/脱离后按全量重算，被合并掉的条目会让后续页整体前移，滚动位置可能有轻微跳动。
- **跨系列顺序只在主系列上**：`mergedSeasonOrder` / `mergedImageOrder` 随主系列失效。成员单独打开时按自己重写后的 `sort` 展示（等于合并期的子序），不保留跨系列交错信息。

## 7. 验证方式

1. 首页把 A 拖到 B：出现翻面浮层、目标卡片出现虚线框与滑入层，松手后出现「已合并到 B」提示，A 从列表消失、B 出现角标与叠层。
2. 点角标展开成员面板，逐项「脱离」，成员卡片立即回到列表。
3. 拖到视口底部保持不动：列表持续下滚，到底后自动加载下一页（卡片数增加）。
4. 打开主系列详情页：季列表包含成员的季并带来源标签，季标题左侧没有拖拽手柄。
5. 全程结束后确认 `/data/series` 中残留 `mergedIds` 为 0，避免测试数据留在真实数据里。

单测覆盖纯逻辑（`test/web/series-merge.test.ts`）与服务端规范化（`test/server/merge-groups.test.ts`），拖拽与动画部分手工验证。
